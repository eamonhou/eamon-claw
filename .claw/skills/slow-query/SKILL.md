# mysql数据库慢查询优化指南

## 何时使用此技能

当用户需要你对mysql数据库进行慢查询优化时

## 提取步骤

1. 调用 lacpm-tool 工具
2. lacpm-tool 需要的参数在工作目录的 config.md 文件中

## lacpm-tool 返回数据说明

```json
{
  "TotalRows": 8000,
  "TotalPages": 68,
  "MatchRows": 70,
  "Ratio": 0.00875,
  "RowsPerPage": 116,
  "alpha_steady": 0.031169779926648426,
  "beta_steady": 0.0009391021728460958,
  "cost_full_scan": 92.93582394131874,
  "cost_index_scan": 7.262948608396907,
  "cost_ratio": 0.07815015029062265,
  "explanation": "物理环境稳态收敛。当前系统负载处于安全基线 (α:0.03, β:0.00)，该字段命中行数 70 处于收敛区间，二级索引物理执行路径综合评分优于全表扫描。"
}
```
- TotalRows: 表总行数
- TotalPages: 预估总数据页
- MatchRows: 条件命中行数
- Ratio: 数据占比
- RowsPerPage: 单页数据条数
- alpha_steady: EWMA 平滑后的稳态 CPU 扰动因子 (α)
- beta_steady: EWMA 平滑后的稳态 I/O 阻尼因子 (β)
- cost_full_scan: 全表顺序扫描物理总代价
- cost_index_scan: 二级索引回表随机 I/O 惩罚总代价
- cost_ratio: 代价放大倍数 (CostIndexScan / CostFullScan)
- explanation: 提供给大模型的白盒化成因定性解释

## la-cpm 原理

LA-CPM 全称
Environment Load-Aware Dynamic Physical Cost Prediction Model （融入环境负载感知的动态物理代价预测模型）

运作原理
传统数据库的优化器（CBO）在决定是走“全表扫描”还是走“索引回表”时，采用的是一种静态的、理想化的数学估算。它假设操作系统的 CPU 永远空闲，磁盘磁头寻道永远没有延迟，且数据分布是均匀的。当主数据库遭遇极端的数据倾斜，同时宿主机硬件资源被其他并发请求大面积挤兑时，传统优化器的这套静态估算机制就会彻底“致盲”，从而选错执行计划，引发灾难性的慢查询爆发。

LA-CPM 的核心原理就是打破这种“静态盲区”，通过将“数据库内部的存储几何特征”与“操作系统底层的实时物理负载”进行跨域咬合与动态重算，其运作流程可以分为以下三个核心步骤：

1. 双向因果视窗的数据抓取
当数据库爆发慢查询时，系统不会做高算力耗散的实时监听，而是采用异步拉取机制。它以这条慢 SQL 的执行周期为中心，向左（爆发前）向右（落盘后）同时拉开一个弹性时间缓冲区（例如向两侧各延伸10秒）。在这个双向视窗内，系统会精准索要两类核心数据：

静态几何特征：在独立的隔离分析读库上，利用非参数化算子全量重算该表在物理引擎层面的真实页数、总行数，以及由于数据倾斜导致的真实条件命中行数。

动态多模态负载：从时序监控基础设施中，按需拉取高密的、消除标签冲突的 CPU 瞬时微观变化率和磁盘块设备真实繁忙率。

2. 内存时间回放与指数消噪
拉取到的有序时序列表在进入计算核心后，系统会在内存中原地“流式重放”这一段历史物理演进过程。为了防止系统毛刺和随机噪声干扰决策，模型采用指数加权移动平均算法进行滤波。算法以慢查询爆发前夕的低负载基线作为初值，随着时间线向前迭代，赋予越邻近慢查询爆发点的数据越高的权重，最终提炼出高保真的稳态 CPU 扰动因子与磁盘 I/O 阻尼因子。

3. 环境共振下的真实代价打分与阶跃裁决
模型将平滑后的环境因子分别注入到两条执行路径的物理代价方程中，开展真实墙钟时间的成本打分：

全表扫描路径：将 CPU 扰动因子引入内存行记录的比较开销中。当 CPU 被严重挤兑时，线程因上下文切换饥饿引发的微观延迟会被等比例放大，还原出真实的全表扫描算力耗散。

二级索引回表路径：这是核心阻尼墙所在。模型将磁盘 I/O 繁忙率直接注入到随机 I/O 惩罚项中，并乘上在分析库上重算出的真实倾斜命中行数。当磁盘处于死锁或高负载状态时，海量非连续的磁头寻道等待会遭遇非线性的级数放大，暴露出真实的随机回表惩罚代价。

最后，系统将两条路径的真实代价在天平上进行数字化比对。一旦由于数据倾斜与硬件饥饿的双向共振，导致回表索引的总代价反超全表扫描，LA-CPM 就会判定传统优化器的底层物理墙遭遇非线性塌方，原地向外弹回核心裁决信号与白盒化的结构账单，指引上层智能体拦截泛化并下发重置指令。

## 禁止事项

- 严禁在未感知系统OS负载的前提下盲目推荐大表全表扫描；
- 严禁在缺乏数据选择性支持时推荐建立重复或极长的前缀复合索引；
- 强行规定任何高危变更动作，如涉及千万级大表的 DROP INDEX、长期阻塞的 ALTER TABLE必须严格遵守人在回路协议，输出格式化工具调用指令后挂起控制流；
- 不允许删除根目录的任何文件；
- 只给出优化建议，不允许执行实际命令对数据库或者系统进行修改；
- 优化建议不必仅局限于数据库方面的优化，还可以考虑缓存、消息队列等其他优化手段；
- 不要提交代码；
